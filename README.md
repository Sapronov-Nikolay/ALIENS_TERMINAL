# 🖥️ ALIENS - TERMINAL (Симулятор терминала по фильмам Aliens)

Интерактивная стилизация компьютерных терминалов из вселенной фильмов «Чужой» (Alien). 
Вы пишете текст в консоль среды разработки (или терминала), на котором запущен сервер. После нажатия `Enter` в браузере посимвольно печатается текст на чёрном экране с эффектом старого CRT-монитора, сопровождаясь механическими щелчками и фоновым гулом.

Проект создан в экспериментальных учебных целях для практики связки **Python (WebSocket-сервер)** и **Frontend (HTML, CSS, JavaScript)**, а также для написания E2E-автотестов.

## ✨ Возможности

- **Связь в реальном времени:** Python-сервер и браузер общаются через WebSocket.
- **Эффект печатной машинки:** Текст появляется посимвольно с настраиваемой скоростью.
- **Генерация звука (Web Audio API):** Звуки щелчков, гула и скрипов генерируются прямо в браузере кодом (без использования mp3/wav файлов).
- **Библиотека звуковых пресетов:** Вы можете переключать звуковые темы (Ностромо, Хадли, Фиорина 161 и др.) прямо на странице через выпадающее меню.
- **Визуальные эффекты:** Мерцание экрана, текстура развёртки, фосфоресцирующее свечение текста, а также анимация «летящей каретки» (принтера).
- **E2E-автотесты:** Проект покрыт тестами на Java (Selenium + JUnit 5 + Allure).

## 🛠️ Установка и запуск

Для работы потребуется `Python 3.8+` и установленная библиотека `WebSocket`.

### 1. Подготовка виртуального окружения
Создайте и активируйте виртуальное окружение (если папки `.venv` еще нет):

### Создание окружения
```bash
python -m venv .venv
```

* Активируйте виртуальное окружение (если оно есть): `.venv\Scripts\Activate`
* Установите зависимость: `pip install websockets`
* Запустите сервер: перейти в папку server с файлом server.py `cd server`, затем ввести команду запуска `python server.py`

## **⚠️ ВАЖНО:** 
После запуска сервера откройте в браузере `http://localhost:8000` и обязательно кликните один раз левой кнопкой мыши по экрану терминала. Это требование современных браузеров (политика Autoplay). **Без первого клика они блокируют воспроизведение звука, и вы его не услышите.**

## 🛠️ Настройка автотестов и генерация Allure-отчёта (Troubleshooting)

При настройке тестов можно столкнуться с двумяклассическими проблемами Maven и Allure. Вот инструкция, как их избежать в будущем.

### 1. Версии зависимостей (pom.xml)

В экосистеме Allure часто меняются имена артефактов. Чтобы не ловить ошибки `ArtifactNotFoundExeption`, используйте проверенную связку:
* `allure-junit5` (версия **2.29.0**) - библиотека для интеграции с JUnit 5. *(Внимание: в версиях 2.35+ она называется `allure-jupiter`)*.
* `allure-maven` (версия **2.12.0**) - плагин для сборки отчёта.
* `<reportVersion>2.30.0</reportVersion>` - версия утилиты для сборки. Версия 2.35.4 и выше часто падают при скачивании с Maven Central.

**Важно:** Если Maven выдаёт ошибку, что не может скачать библиотеку - он кэширует эту ошибку. Вым нужно удалить папку с проблемной библиотекой из `C:\Users\<Имя_пользователя>\.m2\repository\io\qameta\allure\` или запускать команды с флагом `-U` (например, `mvn clean test -U`).

### 2. Связка путей к результатам тестов

По умолчанию JUnit-тесты с Allure сохраняют результаты в папку `allure-results` в корне проекта. А плагин `allure-maven` ищет их в `target/allure-results`. Из-за этого при запуске `mvn allure:serve` выпадает ошибка `Directory ... not found`.

**Решение:** Настроить плагин `maven-surefire-plugin` так, чтобы он явно указывал тестам, куда сохранять результаты.

В `pom.xml` в блоке плагин `maven-surefire-plugin` нужно добавить:
```xml
<configuration>
  <argLine>
    -javaagent:"${settings.localRepository}/... .jar"
  </argLine>
    <systemPropertyVariables>
      <allure.results.directory>${project.build.directory}/allure-results</allure.results.directory>
    </systemPropertyVariables>
</configuration>

```
* `${project.build.directory}` — это системная переменная Maven, которая всегда указывает на папку `target`.
* Теперь тесты и сборщик отчета смотрят в одно и то же место.

### 3. Как запускать тесты и смотреть отчёт

1. Запуск тестов:
```bash
mvn clean test
```
2. Генерация и открытие отчета в браузере:
```bash
mvn allure:serve
```
*Чтобы выйти из режима просмотра и вернуть управление терминалу, нажмите `Ctrl + C`)*

3. Если `allure:serve` не открывает браузер, сгенерируйте статичный HTML-отчёт:
```bash
mvn allure:report
```
*Затем откройте файл `target/site/allure-maven-plugin/index.html` в любом браузере.*


### 💡 Технические фишки проекта

1.  **Чистый Web Audio API (без аудиофайлов):** В проекте нет ни одного файла `.mp3` или `.wav`. Все звуки (щелчки реле, шум принтера, скрипы каретки, фоновый гул) генерируются математически прямо в браузере с помощью осцилляторов и фильтров.
2.  **Архитектура WebSocket:** Мгновенная двусторонняя передача сообщений из консоли Python в браузер с использованием асинхронности (`asyncio`).
3.  **Атмосферный UI/UX:** Эффект старого ЭЛТ-монитора (CRT), развертка, мерцание, фосфорное свечение текста и анимированная «летящая каретка» принтера.
4.  **Гибкая система пресетов:** Легко добавить новый звук — достаточно дописать один блок с настройками в `soundPresets.js`, и он автоматически появится в выпадающем меню на сайте.
5.  **Покрытие E2E-автотестами:** Проект тестируется через Selenium (Java) с проверкой статуса связи, активности аудио-контекста и корректного вывода текста на экран.
